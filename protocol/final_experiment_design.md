# Final inferential experiment — frozen design and analysis plan

**Status:** `FROZEN 2026-09-05` · branch `saadat-pipeline-validation` ·
manifest `config/final_design_manifest.json` · config `config/experiment.yaml` `final:`

This is the pre-registered inferential design. Pilot Pass 2
(`protocol/pilot_pass2.md`) was plumbing + localization only and is **not** its
basis. The grid and the transition interval below are derived from architecture
geometry, not from any observed pilot effect. Do not edit this file, the frozen
config block, the benchmark, the prompt, the scorer, the temporal generator, or
W = 256 without re-freezing.

---

## 1. Sample

| quantity | value |
|---|---|
| items | **240** (48 per fact type) |
| fact types | numerical, temporal, entity-attribute, multi-hop (paper: *compound relational*), contradictory |
| seeds | **[0, 1, 2, 3, 4, 5, 6, 7]** — fixed across arms and pressures |
| arms | transformer (reference), mamba2, deltanet, gated_deltanet |
| model-tat targets | 12 (below) |
| generations | 4 × 240 × 12 × 8 = **92,160** |

`n_temporal = 48` → the direction × position × density 2×2×2 factorial is exactly
balanced at 6 per cell. Compound relational keeps the raw `fact_type="multi-hop"`
for compatibility; the paper-facing label is *compound relational* and the text
must state it is a co-located two-clause relational target, **not** distributed
multi-hop reasoning.

## 2. Pressure grid (model_tokens_after_target)

Frozen: **[150, 180, 205, 220, 235, 250, 265, 285, 315, 380, 520, 760]**.

| role | targets | purpose |
|---|---|---|
| control anchors | 150, 180 | pooled benchmark-control (target fully in exact attention) |
| primary transition | 205, 220, 235, 250, 265, 285 | dense sampling across the compression boundary |
| recurrent anchors | 315, 380, 520, 760 | retrieval from compressed memory, near→far |

**Derivation (geometry, not tuning).** W = 256; the largest tokenised target span
observed is 17 (compound relational); `max_new_tokens = 12`. The interval in which
the target span is crossing the compression boundary during prefill+generation is
about `[W − 2·(span + gen), W + gen] = [198, 268]`, rounded to
**`transition_interval = [200, 270]`**. The six transition targets bracket it with
two anchors just inside the window and one just past it. Pilot Pass 2's observed
knees (~213 transformer, ~244–246 AHN on the balanced grid) are **not** the basis
for any boundary here. W stays an architectural reference and is never equated with
an empirical K.

Each target maps to a per-fact-type `requested_tokens_after_target` in
`config/final_calibration.json` (built by `scripts/full_run_dryrun.py`, no model;
overhead 53–63 tokens differs by type). The scientific grouping key is
`intended_model_tokens_after_target` (`schema.pressure_group_key`); curves are
fitted/plotted against realised `model_tokens_after_target`.

## 3. Benchmark-control validity (per fact type)

Evaluated on the pooled control anchors (intended 150 + 180),
`full_run.control_validity` / `acceptance.control_validity`. Floor only — no
upper-bound / red-flag gate on a high valid control accuracy (spirit of #5a).

- **Non-temporal:** PASS if strict ≥ 0.85; WARNING if strict in [0.70, 0.85) or
  malformed > 0.05 or abstention > 0.10; **FAIL if strict < 0.70** → benchmark
  invalid for that type, excluded from the H1 primary (pre-registered rule).
- **Temporal:** judged on `answered_valid` accuracy (PASS ≥ 0.85), abstention
  tracked separately (WARNING if abstention ∈ [0.40, 0.60]); FAIL if
  `answered_valid` < 0.70 or abstention > 0.60.

## 4. Inferential resampling

**Primary:** two-level (hierarchical) cluster bootstrap —
`stats.hierarchical_bootstrap`. Resample `item_id` clusters with replacement, then
resample seed realisations with replacement within each sampled item; matched
architecture × pressure observations travel with their (item, seed) unit so paired
contrasts stay paired. 2000 replicates, percentile 95% CIs, Holm correction within
each hypothesis family. The legacy seed-only bootstrap (`cluster_bootstrap_ci`,
`bootstrap_statistic`) is retained as a robustness / sensitivity check. No GLMM,
no statsmodels.

## 5. #17 — baseline / null policy (Policy A)

Raw strict production accuracy is the **sole** primary H1/H2 accuracy endpoint. No
baseline-adjusted primary, no universal chance correction, no fake 0.2 correction
for free-response types. Temporal stays raw strict in primary analyses and
additionally reports `answered_valid_accuracy` + `abstention_rate`; an explicit
`baseline_adjusted_accuracy(..., 0.5)` for temporal is appendix/sensitivity only.
Target-removed / forced-answer diagnostics stay construct-validation evidence only.
Resolved **for this inferential protocol**; not a claim that the general
free-response-null problem is theoretically solved (`open_decisions.md` #17).

## 6. H1 — non-uniform degradation across information types

**Endpoint.** `A_transition(type)` = mean raw strict accuracy across the intended
targets **[205, 220, 235, 250, 265]**, pooling the 3 AHN arms (transformer is a
reference curve, not pooled). `h1_degradation.a_transition`.

**Primary test.** The 10 pairwise fact-type `A_transition` differences
(`h1_degradation.a_transition_contrasts`): hierarchical-bootstrap 95% CIs, Holm
adjustment. **H1 supported if at least one Holm-adjusted pairwise CI excludes
zero.**

**Companion omnibus.** Fact-type-label permutation test on the dispersion (SD) of
the five `A_transition` means (`h1_degradation.a_transition_omnibus`). Not the
primary.

**Pre-registered temporal sensitivities.** (A) exclude temporal; (B) substitute
temporal `answered_valid_accuracy`. Both reported beside the primary.

## 7. H2 — concentrated vs gradual collapse, and architecture comparison

`h2_threshold.transition_summary`.

- **Primary descriptive quantity:** per-architecture isotonic 90→10 transition
  width, hierarchical-bootstrap CI. **Concentrated** if CI upper < 128 tokens
  (0.5 W); **gradual** if CI lower > 256 tokens (W); **intermediate** otherwise.
- **Confirmatory shape comparison:** smooth fit vs break-allowed fit with the
  break **fixed at W = 256** (`shape_test`, AIC / RSS). Break location is a
  disclosed analysis parameter, not a claimed published value.
- Also frozen: `A_transition(AHN pooled) − A_transition(transformer)` over
  `[200, 270]` (hierarchical CI); `A_recurrent` per arm = mean strict accuracy over
  intended targets ≥ 315 (hierarchical CI vs 0); descriptive K per arm (0.5
  crossing) with a CI — **descriptive only, never a threshold hypothesis**. No
  published T; `config.compression_threshold(strict=True)` still raises.

## 8. H3 — does behavioral uncertainty signaling track retrieval failure?

`h3_calibration.behavioral_signaling` / `h3_calibration.gap_change`. Phrase as
uncertainty / failure *signaling*, never as the model "knowing" its memory is gone.

**Behavioral primary,** over `model_tokens_after_target ≥ W + 16`:

- `appropriate_abstention_rate` = P(abstained)
- `unsignalled_failure_rate` = P(wrong-valid OR malformed), wrong-valid = answered,
  not malformed, `correct == 0`

Primary comparisons: each AHN arm vs transformer (hierarchical bootstrap, Holm).

**Secondary factual calibration** (`answered_valid` only). Primary secondary test:
change in the confidence-minus-accuracy gap from the control anchors to
`[200, 270]`, per arm (`gap_change`). ECE / Brier / CWR descriptive with CIs.
Abstention confidence is reported separately from factual confidence.
`sequence_probability` confidence is PROVISIONAL; a length-normalised sensitivity
is pre-registered if computable from stored outputs without a GPU rerun.

## 9. Temporal

Unchanged generator. Required sensitivity outputs: H1/H2 excluding temporal; H1/H2
with temporal `answered_valid_accuracy`; response-bias marginals
(`report.temporal_response_table`); `answered_valid_accuracy` + `abstention_rate`
in every temporal table. Any item-level temporal exclusion based on control
abstention > 0.80 is sensitivity-only and cannot affect a primary analysis.

## 10. Stopping / exclusions

No optional stopping — run the entire frozen design. No trial-level exclusions for
abstention / malformed / wrong-valid (they are outcomes). A verified
environment/plumbing failure on an arm → rerun that arm under the identical frozen
protocol. A non-temporal fact type that FAILs §3 → reported benchmark-invalid and
excluded from the H1 primary per the pre-registered rule.

## 11. What is frozen / held identical to every prior run

benchmark items · production `_PROMPT` + per-type `answer_hint` (SHA-256 in the
manifest) · scorer semantics + `SCORER_VERSION` · repaired temporal generator ·
W = 256 · `max_new_tokens = 12` · greedy decoding. `main` is untouched. No GPU was
used to produce this design or the calibration.
